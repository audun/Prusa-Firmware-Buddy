# CORE One quick start printer profiles

PrusaSlicer printer presets for the CORE One and CORE One+ that shorten the
time from "Print" to the first extruded line when printing again right after
a print or a preheat. They are the stock `Prusa CORE One 0.4 nozzle` and
`Prusa CORE One HF0.4 nozzle` printer presets with a different start and end
G-code; machine limits and all print and filament profiles stay stock. The
start G-code probes PLA and PETG at print temperature minus 10 °C (cooling
with the fan when the nozzle is hotter), skips the drop to idle temperature
when no heat soak is expected (no minimal chamber temperature and a bed at
60 °C or less), and purges a half length line. The end G-code disables only
the E motor. With no flags set the profile runs on current stock firmware
and homes with a plain `G28`; `G28 Q` is emitted only with `QUICKSTART_FW`,
because on today's firmware Z stays trusted across prints and `G28 Q` would
skip Z homing and the steel sheet detection. See `../print_startup_cycle.md` for the analysis
behind it.

## Flags

Flags are keywords in Printer Settings → Notes, each on its own line. They
are off in the shipped files.

| Flag | Effect | Firmware |
|------|--------|----------|
| none | Behaviour described above, plain `G28`, stock `G29 P1` probing, `G29 G` + `M109 R` before probing, no Z alignment | Current CORE One firmware (the `M115 U` line is taken from the stock preset, so older firmware gets the usual update suggestion) |
| `QUICKSTART_FW` | `G28 Q` homes only axes the firmware does not trust, `G29 P7` verifies the stored mesh and re-probes only on mismatch, `G29 G S<probe temp>` reheats the nozzle near the end of the soak, adds `M862.6 P"Quick start"` | Firmware with the quick start features (pre-print prep with trust tracking, mesh verify, soak reheat). Not in a release yet. Never set it on stock firmware: `G29 P7` is rejected there and the print continues with an empty or stale mesh, and `G28 Q` skips Z homing and sheet detection. The `M862.6` line makes stock firmware show the unsupported features warning first, unless the Firmware hardware check is set to Ignore |
| `QUICKSTART_KEEP_WARM` | End G-code leaves the nozzle at the filament idle temperature (170 °C when unset) instead of turning it off | Any; the firmware safety timer turns the heater off after 30 minutes |
| `QUICKSTART_Z_ALIGN` | End G-code runs `G162 Z R0` (Z alignment, stay at the bottom) | Only together with `QUICKSTART_FW`, needs `G162 Z R` support. Without `QUICKSTART_FW` it is ignored, because stock firmware would align and return to Z 50, adding about 30 s per print |

## Install

The file name, without `.ini`, becomes the preset name.

1. Install the stock CORE One printer (0.4 or HF0.4 nozzle) in the
   Configuration Wizard, so the parent preset named by `inherits` and the
   `@COREONE` filaments exist.
2. Close PrusaSlicer.
3. Copy the `.ini` file(s) into the user printer folder:
   - Linux: `~/.config/PrusaSlicer/printer/`
   - Windows: `%APPDATA%\PrusaSlicer\printer\`
   - macOS: `~/Library/Application Support/PrusaSlicer/printer/`
4. Start PrusaSlicer and pick `Prusa CORE One 0.4 nozzle - quick start` or
   `Prusa CORE One HF0.4 nozzle - quick start` under the user presets. Print
   and filament profiles for the CORE One stay compatible.

File → Import → Import Config also works but is not recommended. PrusaSlicer
2.9.x builds a print, a filament and a printer preset from one imported file.
These files contain printer settings only, so it also creates and selects a
print and a filament preset made of built-in defaults, ignores the `inherits`
line, and keeps the printer preset as an unsaved external preset named after
the file. If you use it, save the printer preset under a name of your choice,
then select stock print and filament profiles again.

## Regenerate

The `.ini` files are generated by `make_quick_start_ini.py`, which holds the
quick start G-code. It needs only Python 3 and fetches nothing, so give it a
`PrusaResearch.ini` vendor bundle, for example the one in the PrusaSlicer
configuration folder (`vendor/PrusaResearch.ini`) or the one the shipped files
were made from:

    curl -fLo PrusaResearch.ini https://raw.githubusercontent.com/prusa3d/PrusaSlicer/version_2.9.6/resources/profiles/PrusaResearch.ini
    python3 -I make_quick_start_ini.py PrusaResearch.ini

It resolves the stock presets with full inheritance and writes every key, so
the result is complete for loading from the user printer folder. Options:

- `-o DIR` writes somewhere else than next to the script.
- `--flags QUICKSTART_FW,QUICKSTART_KEEP_WARM` writes test variants with the
  flags already in the notes and in the file name.
- `--print-start-gcode` and `--print-end-gcode` print the G-code, for
  comparing against the stock G-code of a newer bundle. Port stock changes
  into the script by hand; it does not merge them.

## Validation

The shipped files and the flagged test variants were sliced headless with
PrusaSlicer 2.9.6 (Flathub build, `--export-gcode`) using the stock
`0.20mm SPEED @COREONE 0.4` print profile and the stock `Prusament PLA
@COREONE` and `Prusament PETG @COREONE` filaments, on a 20 mm cube and a
150 x 150 x 2 mm plate. Every placeholder expression evaluated (no `{` or `[`
left in the output), the `M555` print area was identical to the stock
preset for both models, and the only differences to the stock start and end
G-code were the ones listed above. PLA (230 / 60) probes at 220 °C with no
idle drop; PETG (250 / 85) probes at 240 °C and keeps the idle drop to
130 °C with the soak.

The same G-code is also available as the printer variant
"Prusa CORE One & CORE One+ (quick start)" on the `quick-start-coreone`
branch of the audun/PrusaSlicer fork.
